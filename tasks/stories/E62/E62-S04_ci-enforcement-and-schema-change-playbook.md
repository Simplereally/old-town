# E62-S04 — Guard rails: CI enforcement and the schema-change playbook

## Epic

E62 — Save and Content Safety

## Dependency chain

- Depends on: E62-S03
- Blocks: none (last story)

## Objective

Make it structurally hard to ship the two mistakes this epic exists to prevent: a schema
change without a migration, and a content removal without a lifecycle entry.

## Required work

- [ ] **Schema-change tripwire**: a test that hashes the current snapshot schema's shape
      (stable serialization of the zod structure — a keys/types walk, or snapshot-test the
      schema's parsed output for the current fixture) and compares against a committed
      expectation file. Changing the schema fails the test until the expectation is
      regenerated — and the regeneration script REFUSES unless `CHARACTER_SNAPSHOT_VERSION`
      was bumped and a migration + fixture for the outgoing version exist. One command:
      `bun scripts/snapshot-schema-check.ts --update`.
- [ ] **Content-removal tripwire**: extend `content:validate` (or a sibling script wired into
      the same npm script) with an id-corpus check: every content id present in the PREVIOUS
      release's id manifest (a committed `content/lifecycle/id-manifest.json`, regenerated by
      the same update flow) must still exist, be aliased, or be tombstoned. Renames therefore
      force an alias; removals force a tombstone; the manifest update is the reviewable diff.
- [ ] **Playbook**: finish `docs/engine/save-migrations.md` — the two flows end-to-end
      (schema change; content rename/removal) as numbered steps, including the E57/E58/E59
      note ("your epic adds a field → here is your 15-minute checklist").
- [ ] Wire both checks into the standard validation set (whatever `bun run test` +
      `content:validate` cover — they must run on every PR, not a special lane).
- [ ] Retro-check: run the id-manifest generation against current content to seed the first
      manifest.

## Acceptance criteria

- [ ] Scratch-branch proofs: (a) add a snapshot field without bumping → CI red with a message
      pointing at the playbook; (b) delete an item from content without a tombstone → red;
      (c) follow the playbook for each → green.
- [ ] Both guard scripts' error messages name the exact fix (not just the violation).

## Validation commands

- `bun run test && bun run typecheck && bun run lint && bun run content:validate`
